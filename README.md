# Face Access Control — проходная офисного кампуса

CV/ML-система принятия решения о проходе сотрудника через турникет по лицу: сравнивает лицо в кадре с галереей сотрудников и выдаёт решение `allow` / `deny` / `manual_review`, при этом сомнительные случаи уходят на ручную проверку охраны, а не открывают турникет автоматически. Архитектура разделена на edge (захват кадра, детекция, локальный кэш) и central (identity-сервис, аудит, мониторинг).

## Как запустить PoC

```bash
pip install -r requirements.txt
python -m poc.demo      # прогоняет happy path + 4 risky-события, печатает decision/reasons/latency
pytest tests/            # smoke-тесты: happy path -> allow, risky path -> hold
```

Demo-данные (галерея из 12 сотрудников, синтетические кадры, 5 событий) уже сгенерированы и закоммичены в `poc/data/`; пересобрать их можно через `python -m poc.build_demo_data`.

## Демонстрируемый сценарий

- **Happy path (allow)**: сотрудник подходит к турникету в рабочее время, лицо уверенно матчится с галереей — турникет открывается автоматически.
- **Risky path (manual_review, offline)**: низкое качество кадра / неуверенный матч / недоступен central-сервис — турникет не открывается автоматически, событие уходит охране на ручную проверку.

## Допущения и ограничения

PoC использует mock-эмбеддинги и mock-liveness вместо реальных моделей (детали и обоснование — `docs/ml.md`, а также таблица выше); демо-галерея — 12 синтетических сотрудников, не сотни тысяч; пороги policy engine эвристические, не откалиброваны на реальных данных. Полный список допущений и нерешённых рисков — `SELF_REVIEW.md`.

## Риски вне MVP

Демографическая проверка порогов, полноценная интеграция с турникетом, реальный обучающий/валидационный датасет для калибровки порогов, нагрузочное тестирование на целевом железе — см. `SELF_REVIEW.md` («Что доработать перед production») и `docs/risks-and-ops.md`.

## Бизнес-ценность

Автоматизация распознавания на проходной сокращает очередь в пиковые часы 8:45–9:45, когда одновременный поток сотрудников создаёт затор на ручной проверке пропусков. Снижается нагрузка на охрану: сейчас ~40 случаев в день требуют ручного разбора при стоимости порядка 120 ₽ за случай, и часть этой нагрузки уходит благодаря автоматическому allow по уверенным совпадениям. Отказ от физических карт снижает расходы на их перевыпуск при утере и логистику выдачи новым сотрудникам. При этом скорость не приносится в жертву безопасности: false accept — это инцидент безопасности, а не UX-проблема, поэтому система намеренно консервативна в порогах и любой неуверенный случай уходит в `manual_review`, а не автоматически открывает турникет. Итог — быстрее для подавляющего большинства проходов и не менее строго для пограничных случаев, чем ручная проверка человеком.
